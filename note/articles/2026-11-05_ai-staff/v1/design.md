## 1. 見出し画像の文言（3案）

タイトル：「それで何が楽になるの？」AI社員を10人作って出た答え

| No | 1行目 | 2行目 | 字数 | ねらい |
|---|---|---|---|---|
| **A（採用）** | AI社員10人 | 何が楽になる？ | 14 | 「AI社員10人」で何の話か分かり、「何が楽になる？」で読者（AIを使っていない社長）自身の疑問をそのまま見せる |
| B | AI社員の育て方は | 新人と同じ | 14 | 記事のたとえ（新人育成）を前に出す。工務店の社長に身近だが、タイトルの問いかけとつながりにくい |
| C | 「それで何が楽に | なるの？」 | 13 | 顧問先の社長の生の一言そのもの。強いが、画像だけでは「AIの話」だと分からない |

### 採用：A「AI社員10人／何が楽になる？」

- タイトルの2つの要素（問いかけ＋AI社員10人）を両方入れられて、15字以内に収まるのはAだけ。
- 2行目を問いかけで終えているので、「楽になった」と言い切らない（本文 見出し4で「時間は測っていない」と書いている内容と食い違わない）。
- タイトルと画像で同じ言葉を繰り返しすぎないよう、画像は「何が楽になる？」と短くした。

## 2. シリーズ配色（提案。以後この3色で統一）

| 役割 | 色 | コード | 理由 |
|---|---|---|---|
| 背景 | 藍（あい） | `#17324D` | noteのタイムライン（白い背景）の中で目立つ濃い色。落ち着いていて、煽りに見えない |
| 文字 | 生成り（きなり） | `#FAF6EE` | 真っ白より柔らかく、木の家・工務店の印象に合う。藍の上で縮小してもはっきり読める |
| 差し色 | 山吹（やまぶき） | `#F2A93B` | 1行目・タグ・飾りの丸だけに使う。藍の上で目に入りやすい |

- フォント：Google Fonts「Noto Sans JP」（太さ900・700。SIL Open Font License）。読み込めないときは Hiragino / 游ゴシック / メイリオ / IPAゴシック の順に代わりの日本語フォントで表示。
- 組み方の型（シリーズ共通）：中央ぞろえ、上に柱のタグ（今回は「AIの使い方」）、1行目＝差し色、2行目＝文字色で一番大きく。
- `note/profile.md` の「見出し画像の配色：未定」は、錦織さんの確認後にこの3色へ書き換えてください（デザイン担当では書き換えていません）。

## 3. ファイル

- `thumbnail.html`（1280×670。文言・色は冒頭の CSS 変数と本文の3か所で変えられる）
- `thumbnail.png`（1280×670。Playwright＋Chromium で書き出し済み）

### 確認したこと

- 主見出し：2行目150px、1行目108px（ルールの72px以上）。タグは32px。
- 文字はすべて端から80pxの内側（実測：左右 137〜1143px、上下 114〜556px）。
- Noto Sans JP の読み込みを確認してから書き出し。PNG を開いて、文字の欠け・切れがないことを確認。
- 横幅360pxに縮めた見え方も確認（2行とも読める。タグの文字は小さいが補助なので可）。
- 写真・顔・社名・ロゴは使っていない（brief に指定なし）。「10人」は10個の丸で表した（人物の絵や作り物の写真は使わない）。

### 作り直すとき（書き出し手順）

```
node -e "const {chromium}=require('playwright');(async()=>{const b=await chromium.launch();const p=await b.newPage();await p.setViewportSize({width:1280,height:670});await p.goto('file://'+process.argv[1],{waitUntil:'networkidle'});await p.evaluate(()=>document.fonts.ready);await p.screenshot({path:process.argv[2]});await b.close();})()" "$PWD/thumbnail.html" "$PWD/thumbnail.png"
```

（Playwright が無い環境では、thumbnail.html を Chrome で開き、開発者ツールの端末表示で 1280×670 にして「スクリーンショットをキャプチャ」）

## 4. 本文の図解案（作るかは錦織さんが選ぶ。作る場合も同じ3色）

### 図解1（おすすめ）：見出し2「新人の育て方と同じ」— 左右2列の対応表

| 新人を育てるとき | AI社員を作るとき |
|---|---|
| 仕事を棚卸しして担当を決める | 作業ごとに担当を決める |
| マニュアル・チェックリストを渡す | 担当ごとにルールを書いた紙（ファイル）を渡す |
| やり方を書いて残す | 手順を書いて残す |
| 朝礼で順番に確認する | まとめ役（ディレクター）が順番に確認する |

- 本文の箇条書き4つと、すぐ後の「仕事を棚卸しして〜朝礼で順番に確認する」を1枚にまとめる。この記事の芯（新人育成と同じ）が一目で伝わる。
- 「やり方を書いて残す」は本文に明示がないので、入れる場合は本文に合わせて文言を確認する。

### 図解2：見出し3「直したところが残る」— ぐるっと回る図

直す（「そこは違う」）→ メモに1行書き足す → AIは次の仕事の前にメモを読む → また仕事をする →（月1回整理して、確認したものは正式なルールに格上げ）

- 数字を入れるなら本文と同じ「193行（10月末時点）」「8月に11件を格上げ」だけ。「193回注意した」とは書かない。

### 図解3：見出し4「私がやることは残る」— 2列

| AIがやる | 人間（社長）がやる |
|---|---|
| 下調べ・質問・構成案・下書き・点検 | 質問に答える／タイトルと構成を選ぶ |
| 文面を作るところまで | 公開・SNS・LINEで届ける／7日後に数字を見る |

- 「楽になった」とは書かず、分担の事実だけを並べる。
